# Default desktop collaboration and the installed plugin

GoFlow supplies default collaboration rules through the machine's global rules and skill; the model does not need built-in GoFlow code. Once the Codex desktop host loads the user MCP or installed plugin, GPT can query quota, route tasks, review results, and accept Go outputs.

The original deployment computer installed and enabled the personal plugin `goflow@goflow-local` (package 1.1.2) using the official desktop-bundled Codex CLI, with personal Marketplace policy `INSTALLED_BY_DEFAULT`. A real fresh host found ten tools each under user MCP `goflow` and plugin MCP `goflow_plugin`, plus the enabled cached skill. The distinct service name avoids collision; all entries reference the same user-installed server and shared state. Use one entry point per operation. [Official local plugin documentation](https://developers.openai.com/plugins/build/plugins)

The repository installer deploys the user MCP, global rules, skill, and restricted local client. It preserves login, primary model, and permissions. Billing confirmations remain false by default, and no additional API is acquired. The author's personal Marketplace, cache, confirmations, logs, and configuration are not shipped; the historical installation does not mean a new computer already has the Marketplace plugin.

To manage GoFlow as a plugin, follow the official local Marketplace process and register a personal catalog. Package only the manifest, skill, documentation, and generated credential-free MCP configuration. Point MCP to the installed local server; do not copy runtime/state/auth/backups into the cache. Use the unique plugin service name `goflow_plugin` and preserve the existing user service. Review and validate this additional local registration; the installer does not overwrite personal Marketplaces.

Older chats may have stale tool catalogs. `scripts/client.mjs` checks user registration, fixed Node/server paths, and explicit plugin/project disablement, then calls the same service over standard stdio. Only the original ten tools are allowed, with JSON arguments on stdin. Commands, roots, executors, and authorization cannot be overridden. Custom CODEX_HOME, project overrides, disablement, or unverifiable configuration are rejected. Off mode prevents delegation while permitting status/usage inspection. [MCP configuration](https://learn.chatgpt.com/docs/extend/mcp)

The rules apply to local coding chats for that computer and Codex host: clear ordinary work prefers Go; complex algorithms, architecture, security, production, and unclear scope remain with GPT; noncoding chat does not call Go. Automatic Go verification currently covers ordinary Node tests. GPT preserves original requirements for other stacks. Global overrides, project rules, different roots, cloud, and web chats may change applicability; natural-language rules are not absolute enforcement of every message. [Global rules](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

A risk regression corrected false positives for explicit constraints such as “do not read credentials.” Only a small set of explicit exclusions is removed during risk classification; the complete task and constraints still reach Go. Actual credential operations and explicit high-risk tasks remain with GPT.

Validation distinguishes real Go tasks, independent fresh-host/CLI checks, and desktop UI restart. The original deployment has evidence of protected-client development, tests, GPT review, and acceptance, and an independent fresh host discovered plugin tools. This does not replace a full desktop UI restart or physical Windows reboot. More detailed local validation and rollback records are kept private without personal paths or runtime state in this repository.

Use the README control script to roll back this repository's user MCP deployment. The original machine's additional desktop plugin has its own ownership-scoped rollback: it removes only its plugin/Marketplace registrations and restores its rules, skill, and routing patch, preserving login and other settings. Active tasks or later changes block rollback. On that original deployment, undo desktop integration before full runtime removal so no plugin points at an uninstalled server. Do not delete the entire Codex configuration directory.
